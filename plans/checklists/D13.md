# D13 — switch monitors mid-session: tester checklist

What this proves: during a live session the shared monitor can be changed **without
reconnecting** — from the host's own window, or from the viewer while it has **control**. The
picture, the cursor and the remote input all move to the new monitor together. A view-only
viewer cannot switch (it would widen what the host chose to show).

How it works: the host announces its monitors (`displays` on the ctl channel) at session start
and after every switch. A switch request (host UI, or the viewer's `seldisp`, honoured only while
control is granted) is handed to the host media thread, which opens the new capture **next to**
the old one, builds an encoder on its device, and only then swaps both in, forces a keyframe and
re-targets the injector (primary → the plain absolute path; any other monitor → its
virtual-desktop rectangle). A failed switch keeps sharing the current monitor and says why. The
switch is **not saved**: Settings → "Monitor to share" stays the default for the next session.

Where the picker is:
* **Host (all OSes):** "Monitor" row on the session card (shown with 2+ monitors).
* **Viewer on Windows:** the monitor drop-down in the top-edge session bar.
* **Viewer on macOS / Linux:** the native **Monitor** menu (checkmark = shared monitor; items are
  disabled with "needs control" while view-only).

Covered on every OS by `cargo test`: the `displays`/`seldisp` wire shapes
(`crates/protocol/src/control.rs`) and the loopback test
`monitor_switch_follows_picture_input_and_the_control_gate`
(`cargo test -p engine --test loopback --features test-hooks`): viewer-initiated switch (new
picture size, encode re-fit to the viewer window, injector target rect), view-only refusal,
host-initiated switch back to the primary path, unknown-id toast.

## Before you start

* A **host with two or more monitors**, ideally of different sizes/scales, one of them not the
  primary (and, on Windows, one placed left of or above the primary, so its coordinates are
  negative).
* D13 builds on both machines. Test each host OS you can: Windows, macOS, Linux X11. (Linux
  Wayland: the portal picks the output, so no list is offered — expected, see step 6.)

For each step write **pass / fail**; for a fail attach a short recording of the controller and
both `app.log` files around it (look for `host: switched to monitor` / `monitor switch to`).

## 1. Viewer switches (control)

1. Connect with control. Expected: the viewer offers every host monitor; the shared one is
   selected/checked.
2. Pick another monitor. Expected: within about a second the picture shows that monitor, sharp
   and with the right aspect (letterboxed if it differs); no reconnect, no black screen.
3. Move the mouse and click/type on the new monitor. Expected: the pointer lands exactly where you
   point (check all four corners), clicks and keys act on that monitor.
4. Switch back to the first monitor. Expected: same as 2–3.
5. Rapidly pick several monitors in a row. Expected: it settles on the last one picked; input
   matches the picture.

## 2. View-only cannot switch

1. On the host, set the permission to **view**. Expected: the viewer's picker turns disabled
   ("needs control"); the picture stays on the current monitor.
2. Set it back to **control**. Expected: the picker is enabled again.

## 3. Host switches

1. On the host's session card, change "Monitor". Expected: the viewer's picture and picker follow;
   viewer input lands on the new monitor.

## 4. Scaling / odd layouts

1. Switch to a monitor with a different DPI scale (Windows 150 %, Retina vs non-Retina). Expected:
   pointer mapping is exact; the cursor image is the right size.
2. Windows: switch to the monitor at negative coordinates. Expected: pointer mapping is exact.

## 5. Failure keeps the session

1. Unplug (or disable) the non-shared monitor, then pick it from a stale picker. Expected: a
   "no longer connected" / "Could not switch monitors" message, the session continues on the
   current monitor, and the picker refreshes.

## 6. Nothing to switch

1. Single-monitor host, or Linux Wayland host. Expected: no picker on either side (the macOS /
   Linux viewer's Monitor menu shows "No other monitors").
