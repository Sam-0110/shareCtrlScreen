# W10 — Service host survives its window closing (tester checklist)

Needs: a real Windows 10/11 host with the installer from this branch (the service
installed), and a second machine to connect from. Logs: the host's `app.log` in
`%APPDATA%\ShareCtrlScreen`, and the service's `sharectrl-service.log` in
`C:\Program Files\ShareCtrlScreen\`.

| Step | Action | Must see |
|---|---|---|
| 1 | Sign in. Look at the notification area (open the `^` overflow if needed) | a ShareCtrlScreen icon; hovering shows "ShareCtrlScreen: reachable while this icon is here" |
| 2 | Open the window from the taskbar, then close it with the X | the window disappears, `sharectrl.exe` is still in Task Manager, the icon stays; `app.log`: `window closed: hidden to the tray, still reachable` |
| 3 | From the second machine, connect to this machine's ID | the host window comes back up on its own with the incoming-connection prompt (Approve mode) or the session starts (password mode). The connection works |
| 4 | During that session, close the host window with the X | the session ends on both sides; the window hides; connecting again from the second machine works |
| 5 | Left-click the tray icon; then right-click → Open | each brings the window back and to the front |
| 6 | Double-click `sharectrl.exe` while the window is hidden | no second `sharectrl.exe`; the hidden window comes back (W4 hand-over) |
| 7 | Right-click the tray icon → Quit | `sharectrl.exe` exits and the icon goes. `sharectrl-service.log`: `the host exited cleanly … not relaunching`. After 30 s it is still not running |
| 8 | Sign out and back in | the host is running again (minimized), the tray icon is back |
| 9 | Task Manager → Details → `sharectrl.exe` → End task | within a few seconds a new `sharectrl.exe` starts; `sharectrl-service.log`: `the host exited abnormally (exit code 0x1); relaunching in 2s`, then a `launched engine pid=…` line. The machine is reachable again from the second machine |
| 10 | End task again 3 times quickly | relaunch delays in the log grow 2 s → 4 s → 8 s → 16 s (backoff), and it does come back each time |
| 11 | Settings → Updates → Update & restart (needs two updater-enabled releases, as U1) | the update installs and the new version comes up once; the service log shows a clean exit for the old host and **no** relaunch of the old exe during the install |
| 12 | Portable / no-service install: run a `sharectrl.exe` with the service not installed, close its window | it quits as before (no tray icon): hiding is for the service host only |

Report back: Windows edition and version, and any step where the machine became
unreachable, the window could not be brought back, two `sharectrl.exe` ran at once, a Quit
was undone by a relaunch, or the update raced a relaunch.
