# D14 — pop out other monitors into separate windows: tester checklist

What this proves: while **controlling**, the viewer can show more of the host's monitors at the
same time, each in its **own window** next to the main one. Each window has its own video
stream, its own picture size and its own mouse mapping. Closing a window stops that stream.
Revoking control closes every pop-out (a view-only peer only sees the main window's monitor).

How it works:
* **Offer:** when the viewer advertises pop-out support (`caps.popout`, new viewers only), the
  host adds one spare video track per other monitor (up to 3) to the offer. Older viewers get the
  usual single track.
* **Opening one:** "Pop out…" (Windows session bar) or **Monitor → Open in New Window**
  (macOS/Linux menu) sends `popout`. The host starts a second capture → encode thread on a spare
  track and lists it in `displays.popouts`. The viewer app opens a window with a native video
  surface of its own and attaches it to that stream.
* **Bandwidth:** the encoder bitrate is split evenly between the live streams.
* **Input:** an ordered `itgt` message tells the host which window's monitor the next mouse
  events belong to. Keys are not positional and go to whatever has focus on the host.
* **Windows backend:** the native video window state (input sink, letterbox size, held keys,
  cursor hiding, top-edge reveal) is now per window instead of process-wide.

Limits: file drop works on the main window only, and shortcut capture (Alt+Tab etc.) only while
the main window has focus. A pop-out of the monitor the main window switches to closes.

Covered on every OS by `cargo test`:
* loopback `popout_window_streams_a_second_monitor_with_its_own_input`: second stream at its own
  size beside the main one; input from each window lands on its monitor; close stops the stream;
  a stale close cannot detach a newer window on the same slot; revoking control closes it;
  view-only cannot open one;
* protocol wire shapes (stream 0 keeps the old `kf`/`vsize`/`cur` bytes);
* transport m-line → slot mapping;
* the input loop sends one `itgt` before a pop-out's first pointer event;
* the shared cursor-image record;
* app window cap and labels.

The Windows crates are type-checked and linted for `x86_64-pc-windows-gnu`. **Not run anywhere
yet:** real windows on any OS. That is what this checklist is for.

## Before you start

* A **host with 2–4 monitors** (different sizes help) and a viewer, both on D14 builds.
* Test each viewer OS you can: Windows, macOS, Linux X11, Linux Wayland.

For each step write **pass / fail**. For a fail, attach a recording and both `app.log` files
(look for `pop-out`, `streaming monitor`, `attached`).

## 1. Open, use, close

1. Connect with control. Open a second monitor in a new window. Expected: a window titled with
   the monitor's name opens and shows it live; the main window keeps showing its monitor.
2. Resize the pop-out. Expected: the picture stays sharp at the new size (re-encoded to fit).
3. Click, drag, scroll and type in the pop-out. Check all four corners. Expected: everything
   lands on that monitor. Then do the same in the main window. Expected: it lands on the main
   monitor, with no stray clicks on the other.
4. Move the host's pointer from one monitor to the other. Expected: the cursor shows in the
   window of the monitor it is on.
5. Close the pop-out with its close button. Expected: it closes, and the host card no longer lists
   it under "Also shown in separate windows".
6. Reopen the same monitor **immediately** after closing it. Expected: it opens and works.
   (Regression check for the slot-reuse race.)

## 2. Several at once (3+ monitors)

1. Pop out every other monitor. Expected: one window each, all live. The video stays smooth and
   only softens when the link is tight (bandwidth is shared).
2. Close them in a different order from opening. Expected: the rest keep working.

## 3. Control and switching

1. On the host, set **view**. Expected: every pop-out window closes, and "Pop out…" / "Open in New
   Window" is disabled.
2. Set **control** again and pop a monitor out. Then switch the main window to that same monitor.
   Expected: the pop-out closes and the main window shows it.

## 4. Session end

1. With pop-outs open, click Disconnect. Expected: every pop-out window closes and nothing is left
   frozen on screen.
2. Repeat, but end the session from the host, and also by pulling the network. Expected: same.

## 5. Windows-specific (per-window state)

1. With a pop-out open, use the main window. Expected: the main window's input still works
   (before D14's Windows fix, the pop-out would have taken the main window's input over).
2. Close the pop-out. Expected: main-window input still works, and the top-edge drawer still
   reveals.
3. Hold a key in the pop-out and click the main window. Expected: no stuck key on the host.

## 6. Older peers

1. New viewer → older host: no monitor pickers appear (an older host does not announce its
   monitors), and viewing and control work as before.
2. Older viewer → new host: the session works exactly as before.
